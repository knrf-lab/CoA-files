Organization vs architecture (organisasi vs arsitektur)

Computer architecture = the logical, programmer-visible design: the instruction set, opcodes, data types, number and size of registers, addressing modes. It answers "How do I design a computer?"

Computer organization = how that design is physically built: control signals, buses, memory technology, the datapath. It answers "How does a computer work?"
▣ METHOD Ask: "Would a programmer writing assembly code notice it?" Yes → architecture. No (only an engineer building it would) → organization.

Example (the classic textbook case)

"Does the CPU have a multiply instruction?" → programmer sees it → architecture.
"Is multiply done by a dedicated multiplier circuit or by repeated addition?" → invisible to the programmer → organization.
"How many registers?" → architecture. "Is the cache made of SRAM?" → organization.

The three core components and HW/SW equivalence

Every computer has: (1) a processor (CPU) to interpret and execute programs, (2) a memory to store both data and programs, (3) an I/O system to move data to and from the outside world.

Principle of equivalence of hardware and software: anything done in software can be done in hardware, and anything done in hardware can be done in software. Hardware is almost always faster; software is more flexible (easy to change). Designers choose based on this speed-vs-flexibility trade-off.

Example: reading a computer ad (slides S1 #8)

"4.20 GHz" → CPU clock rate, 4.2 × 10⁹ cycles/s, so one cycle ≈ 0.238 ns ().
"32GB DDR4 SDRAM" → main memory: 32 × 2³⁰ bytes of dynamic RAM ().
"128KB L1 cache" → the small fast memory closest to the CPU ().

Standards organizations let equipment from different makers work together: IEEE (components, signalling, data representation, e.g. floating point) and ISO (international). Some are informal trade groups.

The two driving factors behind all of this: cost and performance (S1 exercise 1).

Moore's Law: the number of transistors on a chip doubles about every 18–24 months (≈ 2 years). It is an observation, not a law of physics, and transistor count is not the same as performance.
If performance doubles every d years:
Performance factor = 2^(years ÷ d)
Execution time ∝ 1 ÷ performance.

Example: older processor quiz Q3, prof's solution

200 s now; performance doubles every 2 years; processor 4 years older.
1. Doublings = 4 ÷ 2 = 2.
2. Factor = 2² = 4. The older CPU is 4× slower.
3. Time = 200 × 4 = 800 s

Example: newer processor cheat sheet P3

60 s now; doubling every 1.5 years; processor 6 years newer.
1. Doublings = 6 ÷ 1.5 = 4.
2. Factor = 2⁴ = 16. Newer → 16× faster.
3. Time = 60 ÷ 16 = 3.75 s
⚠ TRAP Older → slower → time gets bigger (multiply). Newer → faster → time gets smaller (divide). Write "older = slower" next to your working so you don't flip it.

Why Moore's Law can't last forever (S1 exercise 3): transistors cannot shrink below the size of atoms; smaller, denser chips produce more heat and power per area; quantum effects make tiny transistors unreliable; and the cost of each new fabrication plant keeps rising (Rock's Law). Growth has already slowed.

This course lives mostly at levels 1–2 (MARIE's machine code and control) and the memory hardware under them.

The von Neumann model and beyond

Von Neumann architecture (almost every general-purpose computer):
• Stored-program concept: instructions and data are stored in the same memory.
• Three hardware systems: CPU (with ALU, registers, control unit), main memory, I/O.
• Instructions are executed sequentially through the fetch–decode–execute cycle ().
• A single path between CPU and memory: the von Neumann bottleneck, because instructions and data compete for it.

Purpose of the processing unit (S1 exercise 2): it fetches instructions from memory, decodes them, and executes them. The ALU does the arithmetic and logic; the control unit directs the flow of data and instructions.

Non-von Neumann designs break one of those rules. The Harvard architecture has separate memories/buses for instructions and data, which removes the shared-path bottleneck. Parallel processing (many cores or many computers working at once) is the most popular non-von Neumann approach.
