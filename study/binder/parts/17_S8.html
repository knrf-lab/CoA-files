Why virtual memory

Virtual memory uses the hard disk as an extension of main memory. Each program gets a large virtual address space, so it can be bigger than the physical RAM, and programmers no longer worry about physical memory limits.

The most common implementation is paging: virtual memory is cut into fixed-size pages, physical memory into frames of the same size.

TermMeaning
Virtual addressthe logical address the program uses
Physical addressthe real location in RAM
Page tablea table in main memory mapping virtual page numbers to physical frame numbers (with a valid bit)
Page faultthe page is not in main memory; it must be copied from disk
MMUhardware that does the translation
TLBa small cache of recent page-table entries, so most translations skip the page table

Address translation

Virtual address = page number | offset
Offset bits = log₂(page size)
Page-number bits = virtual address bits − offset bits
Physical address = frame number | same offset
▣ METHOD
1. Split the virtual address. 2. Look the page number up (TLB first, then page table). 3. Valid → replace the page number by the frame number, keep the offset. 4. Not valid → page fault: the OS loads the page from disk into a free frame (replacing one if needed), updates the table, and the instruction restarts.

Example

16-bit virtual addresses, 4 KB (2¹²) pages → offset 12 bits, page number 4 bits.
VA 0x3A7F → page 3, offset A7F.
Page table: page 3 → frame 5 (valid).
PA = frame 5 | A7F = 0x5A7F
If page 3 were marked invalid → page fault.
✔ Same idea as cache fields: the low bits (offset) pass through unchanged; only the high bits are translated.

Real-world memory management

Intel Core i9: three cache levels. L1 is split into an instruction cache and a data cache, each with its own TLB. L1 is 8-way, L2 16-way, L3 11-way set associative.

MIPS: an on-chip MMU maps virtual to physical addresses; caches are initialized by boot code; the TLB is managed by software; supports both big- and little-endian.
