C · Calculation toolkit: doing the arithmetic by hand

Cheat sheet: T1 T9 T10 · Used in: Q1, Q2, Q4, Q5, Q8, P1, P2, P8, P9

Almost every CoA calculation is one of five moves: a power of 2, a base conversion, hex addition/subtraction, splitting a bit string, or a "divide by 2ᵏ". Learn these once and the rest of the binder is easy.

1 · Powers of 2 you must know by heart

Prefix rule: K = 2¹⁰, M = 2²⁰, G = 2³⁰ (for memory sizes).
So 4M = 2² × 2²⁰ = 2²², 16K = 2⁴ × 2¹⁰ = 2¹⁴, 8M = 2²³, 2M = 2²¹.
log₂ of a power of 2 is just the exponent: log₂(1024) = 10, log₂(16) = 4.
Multiplying powers: add exponents. 2⁴ × 2⁸ = 2¹². Dividing: subtract. 2²⁴ ÷ 2⁴ = 2²⁰.
⚠ TRAP For speed (GHz, MHz) and time (ns), the prefixes are decimal: 1 GHz = 10⁹ Hz, 1 ns = 10⁻⁹ s. Only memory sizes use powers of 2.

2 · Base conversions by hand

Binary → decimal: add the place values of the 1-bits.
Place values: … 128 64 32 16 8 4 2 1
1100 1000₂ = 128 + 64 + 8 = 200

Decimal → binary: subtract the largest power of 2 that fits, repeat.
200 − 128 = 72 − 64 = 8 − 8 = 0 → bits 128, 64, 8 → 1100 1000

Hex → decimal: digits × powers of 16 (1, 16, 256, 4096).
0x3C7 = 3·256 + 12·16 + 7 = 768 + 192 + 7 = 967

Decimal → hex: divide by 16, keep remainders (read upward).
200 ÷ 16 = 12 r 8 → C8. 60 ÷ 16 = 3 r 12 → 3C
Hex ↔ binary is the one you use most: each hex digit is exactly 4 bits.
0x3C7 → 3 = 0011, C = 1100, 7 = 0111 → 0011 1100 0111
1011 0110₂ → 1011 = B, 0110 = 6 → 0xB6
Group from the right; pad the left group with 0s.
1 0110 1101 → 0001 0110 1101 → 0x16D
✔ Learn the 16 rows in Tab T () until you can write them without thinking. A, C and F (1010, 1100, 1111) come up constantly.

3 · Hex addition and subtraction (MARIE's AC works in hex)

Work digit by digit from the right, like decimal, but carry/borrow at 16.
Add: 0x2A + 0x3C: A + C = 10 + 12 = 22 = 16 + 6 → write 6, carry 1. 2 + 3 + 1 = 6 → 0x66 (= 42 + 60 = 102 ✓)
Subtract: 0x0035 − 0x0010 = 0x0025 (no borrow needed).
0x0100 − 0x0001: 0 − 1 needs a borrow: 16 − 1 = F, then borrow again → 0x00FF.

Example (quiz Q4)

AC = 0035, M[155] = 0010, instruction Subt 155. AC ← 0035 − 0010 = 0025 (hex).
In decimal that is 53 − 16 = 37, and 0x25 = 37 ✓. Give the answer in hex, the way the prof does, and add the decimal if you like.
⚠ TRAP When a MARIE value is written as hex (0035), do the arithmetic in hex. 0035 − 0010 is 0025 hex, not 25 decimal.

4 · The "drop bits / keep bits" trick (dividing by 2ᵏ)

For any binary number:
⌊x ÷ 2ᵏ⌋ = drop the lowest k bits.
x mod 2ᵏ = keep only the lowest k bits.
In hex, each hex digit is 4 bits, so ÷16 = drop the last hex digit, mod 16 = keep the last hex digit.
0x5A3C8F ÷ 16 → 0x5A3C8 · 0x5A3C8F mod 16 → 0xF
✔ This is exactly how cache mapping works (): the block number is "address ÷ block size" (drop the offset bits), and the cache line is "block mod lines" (keep the index bits). You never need long division.

5 · Splitting a bit string into fields

Example: split 24 bits as Tag 10 | Index 10 | Offset 4 quiz Q8

0x5A3C8F → 0101 1010 0011 1100 1000 1111 (24 bits)
Count from the right: offset = last 4 bits 1111; index = next 10 bits 11 1100 1000; tag = the 10 bits left 0101 1010 00.
Index → decimal: 11 1100 1000 = 512 + 256 + 128 + 64 + 8 = 968. In hex: regroup from the right, 11 1100 1000 = 0x3C8.
✔ Always count field widths from the right (low bits). The left-most field gets whatever is left, and it may not be a multiple of 4.
