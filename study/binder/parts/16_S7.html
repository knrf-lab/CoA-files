Memory basics and types

  • Latency: time for one memory access to complete.
  • Bandwidth: bits/bytes transferred per second.
  • Static memory keeps its state while power is on; dynamic memory must be refreshed constantly.
  • Volatile memory loses its contents when power is off (RAM); nonvolatile keeps them (ROM, flash, disk).
  • RAM: every cell has an address and can be accessed in any order in the same time (vs sequential-access memory like tape).

The memory hierarchy and locality

Registers → Cache → Main memory → Secondary storage (disk)

Goal (S6-7 exercise 1): give the speed of the fastest memory at roughly the cost per bit of the cheapest, by keeping the data the CPU needs right now in the small, fast levels.

Temporal locality: data used recently will probably be used again soon.
e.g. a loop counter, the instructions inside a loop.
Spatial locality: data near a recently used address will probably be used soon.
e.g. walking through an array, sequential instructions.

Caches exploit both: they keep recently used blocks (temporal) and load a whole block of neighbouring bytes on each miss (spatial).

Cache hits, misses and access time

The CPU checks the cache first. Found → hit. Not found → miss: the whole block is copied from main memory into the cache, then used.

Hit rate H = hits ÷ total accesses · miss rate = 1 − H
Effective access time EAT = H × tcache + (1 − H) × tmemory

Example

Cache 10 ns, main memory 200 ns, hit rate 99%.
EAT = 0.99 × 10 + 0.01 × 200 = 9.9 + 2 = 11.9 ns — nearly cache speed with a 99% hit rate.

The three mapping schemes

SchemeWhere can a memory block go?Address fieldsPros / cons
Direct mappedexactly one line: line = block mod (# lines)Tag | Index | Offsetsimple, cheap; conflict misses when two hot blocks share a line; no replacement choice
Fully associativeany lineTag | Offset (no index)most flexible; must search every line in parallel → expensive
N-way set associativeany of the N lines of one set: set = block mod (# sets)Tag | Set | Offsetcompromise: good hit rate, moderate cost

Address fields: Tag | Index (Set) | Offset

Address bits = log₂(memory size in addressable units)
Offset = log₂(block size) — which byte inside the block
Index = log₂(# cache lines) — which line (direct mapped)
Set = log₂(# sets), # sets = lines ÷ N — which set (N-way)
Tag = address bits − index (or set) − offset — which memory block is in the line
Fully associative: Tag = address bits − offset
# main-memory blocks = memory size ÷ block size
Block number = ⌊address ÷ block size⌋ (drop the offset bits)
Line = block mod lines · Set = block mod sets (keep the low bits)
Tag value = ⌊block ÷ lines⌋ (the remaining high bits)

Worked example quiz Q8, prof's solution

2²⁴ bytes, byte-addressable, direct-mapped, 1024 blocks of 16 bytes.
1. Memory blocks = 2²⁴ ÷ 2⁴ = 2²⁰
2. Format: address = log₂(2²⁴) = 24 bits. Offset = log₂16 = 4. Index = log₂1024 = 10. Tag = 24 − 10 − 4 = 10. → Tag 10 | Index 10 | Offset 4
3. Map 0x5A3C8F
Step 1: binary 0101 1010 0011 1100 1000 1111
Step 2: split from the right (10 | 10 | 4): offset 1111, index 11 1100 1000, tag 0101 1010 00
Step 3: index → decimal 512 + 256 + 128 + 64 + 8 = 968
Hex shortcut: block = drop the last hex digit = 0x5A3C8; line = low 10 bits = 0x3C8 = 968; tag = 0x5A3C8 ÷ 1024 = 0x168 = 360.

Same memory, other mappings

Fully associative: no index → Tag 20 | Offset 4. 0x5A3C8F → tag 0x5A3C8.
4-way set associative: 1024 ÷ 4 = 256 sets → set 8 bits → Tag 12 | Set 8 | Offset 4. 0x5A3C8F → 0x5A3 | 0xC8 | 0xF → set 200.

Example cheat sheet P8

2¹⁶ bytes, 64-line cache, 8-byte blocks. Blocks = 2¹³. Direct: offset 3, index 6, tag 7. 0xBEEF = 1011111 | 011101 | 111 → line 29, tag 95. 2-way: 32 sets → 8 | 5 | 3 → 10111110 | 11101 | 111 → set 29, tag 190.
⚠ TRAP For a set-associative cache the middle field is log₂(sets), not log₂(lines). Fewer index bits means more tag bits.

Tracing a reference string

▣ METHOD For each reference: (1) find its line (direct) or set (set-assoc.), (2) hit if that block is already there, otherwise miss and load it (evicting according to the policy), (3) write the cache contents after each step.

Replacement policies

Needed only when a miss happens and the line/set is full. Direct-mapped caches have no choice: the mapping fixes the line.

PolicyEvicts
FIFOthe block that was loaded earliest. Hits change nothing.
LRUthe block used least recently. Every hit refreshes the block.
LFUthe block with the fewest uses
Randoma random block

Example where LRU and FIFO differ cheat sheet P11b

Fully associative, 2 blocks, refs 1, 2, 1, 3, 1, 2.
LRU: 1 M · 2 M · 1 H (1 is now most recent) · 3 M evicts 2 · 1 H · 2 M → 2 hits
FIFO: 1 M · 2 M · 1 H (order unchanged: 1 is still oldest) · 3 M evicts 1 · 1 M · 2 M → 1 hit

Example

A loop writes to variable X 100 times while X stays cached.
Write-through: 100 memory writes.
Write-back: 0 memory writes during the loop; 1 write when X's block is finally evicted (its dirty bit is set).
