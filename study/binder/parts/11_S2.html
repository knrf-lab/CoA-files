Binary and hexadecimal

A computer stores everything as bits (0/1). Numbers use positional notation: each position is worth a power of the base.

Unsigned value = Σ bit × 2^position (position 0 is the rightmost)
n bits give 2ⁿ patterns → unsigned range 0 … 2ⁿ − 1
8 bits: 0…255 · 12 bits: 0…4095 · 16 bits: 0…65,535

Hexadecimal (base 16, digits 0–9, A–F) is shorthand for binary: 1 hex digit = 4 bits, so 1 byte (8 bits) = 2 hex digits and a 16-bit MARIE word = 4 hex digits.

Bytes, MSB and LSB

A 32-bit value has 4 bytes. Written in hex, each byte is one pair of digits:

0x778899AA778899AA
roleMSBLSB

The most significant byte (MSB) is the leftmost pair; the least significant byte (LSB) is the rightmost pair. The most significant bit is the single leftmost bit.

Example: middle bytes quiz Q1, prof's solution

0x778899AA → drop the highest byte (77) and lowest byte (AA) → middle bytes 88 and 99.
16-bit code: 8899. Binary: 8 = 1000, 8 = 1000, 9 = 1001, 9 = 1001
0x8899 = 1000 1000 1001 1001

0xC0FFEE42 → MSB C0, LSB 42 → 0xC042 = 1100 0000 0100 0010

Two's complement: negative integers

In n-bit two's complement, the leftmost bit has weight −2ⁿ⁻¹ instead of +2ⁿ⁻¹.
Range: −2ⁿ⁻¹ … 2ⁿ⁻¹ − 1
8-bit: −128 … 127 · 16-bit: −32,768 … 32,767
Sign check: MSB (leftmost bit) 0 → non-negative, 1 → negative.
In hex: first digit 0–7 → positive, 8–F → negative.

Why use it? The same adder circuit works for positive and negative numbers, and there is only one zero.

▣ METHOD: write −x
1. Write +x in n bits. 2. Flip every bit. 3. Add 1.

METHOD: decode a negative pattern
Value = (unsigned value) − 2ⁿ.
Or: flip the bits, add 1, read the magnitude, put a minus sign.

Example: −10 in 8 bits Study Guide p.3

+10 = 0000 1010 → flip → 1111 0101 → +1 → 1111 0110 (= 0xF6)
Check: 0xF6 = 246 unsigned; 246 − 256 = −10 ✓

Example: −37 in 8 bits cheat sheet P2b

+37 = 0010 0101 → 1101 1010 → +1 → 1101 1011 = 0xDB

Example: decode 0xF3A0 (16-bit) cheat sheet P2a

First digit F ≥ 8 → negative. Unsigned = 15·4096 + 3·256 + 10·16 = 62,368.
Value = 62,368 − 65,536 = −3168

Example: decode 0xFFD6 (16-bit)

Unsigned 65,494 → 65,494 − 65,536 = −42. (Flip: 0000 0000 0010 1001, +1 → 0010 1010 = 42 ✓)

Sign extension: to widen a two's-complement number, copy the sign bit to the left. −5 = 1111 1011 (8-bit) → 1111 1111 1111 1011 (16-bit).

Overflow: adding two positives that gives a "negative" (or two negatives giving a positive) means the result did not fit. 8-bit: 100 + 50 = 150 > 127 → the bits read as −106.

Characters: the same bits, different meanings

Characters are stored as numeric codes. ASCII uses 7 bits, stored in one 8-bit byte: 'A' = 0x41, 'M' = 0x4D, 'E' = 0x45, 'a' = 0x61, '0' = 0x30 (table ).

A bit pattern has no meaning by itself. 0x4D45 can be the text "ME", the integer 19,781, or a MARIE instruction (4 = Subt, address D45). The interpretation depends on what the program does with it.

Example: packed characters quiz Q2, prof's solution

"ME" stored as 0x4D45 (one character per byte).
Binary: 4 = 0100, D = 1101, 4 = 0100, 5 = 0101 → 0100 1101 0100 0101
Read as two's complement: the MSB (leftmost bit) is 0 → positive (+19,781).

Endianness: byte order in memory (urutan byte)

In a byte-addressable memory, a multi-byte value occupies several consecutive addresses. Endianness is the order its bytes go in.
Big endian: the most significant byte at the lowest address ("big end first").
Little endian: the least significant byte at the lowest address.
Only the byte order changes; the bits inside each byte are untouched.
▣ METHOD
1. Pad the value to its full width (32-bit = 8 hex digits).
2. Split into bytes (pairs of hex digits).
3. Big: write them left to right from the start address. Little: write them in reverse.
Reading memory back: undo the steps.
